## I01

**선택이 끝난 요청의 분류 생략.**

- 제안: 유효한 모델·effort가 모두 지정됐거나, 호환 후보가 하나거나, 검증된 결정적 규칙이 선택을 확정하면 Decisions 호출을 생략한다.
- 경계: 모델만 지정되고 effort가 미정이면 선택이 남아 있을 수 있다. 짧은 문장이라는 이유만으로 쉬운 작업으로 처리하지 않는다.
- 확인: 생략 사유와 호출 수를 기록하고, 입력·권한·예산 검사는 계속 적용한다. [E04](EVALUATION.md#e04).

## I02

**부족한 사실과 사용자 결정 구분.**

- 제안: 저장소에서 얻을 수 있는 사실은 읽고, 원하는 결과를 정하는 중요한 선택은 질문하며, 사소한 가역적 선택은 가정을 기록하고 진행한다.
- 경계: 라우터가 분류를 확신하지 못하는 상황을 사용자에게 매번 넘기지 않는다. 정보가 충분하면 호환되는 기본 경로를 사용한다.
- 확인: 비슷한 요청에 서로 다른 누락 원인을 넣은 fixture에서 다음 동작이 적절한지 검사한다. [E04](EVALUATION.md#e04).

## I03

**검증 가능한 작업의 저비용 우선 실행.**

- 제안: 유용한 독립 검사가 있는 가역적 과제에서는 낮은 자원으로 실행하고, 실패 근거가 확인되면 한 차례 추가 실행하는 정책을 비교한다.
- 경계: 검사 통과가 실제 정확성을 충분히 뒷받침하는지 먼저 확인한다. 자체 평가 문장이나 얕은 테스트만으로 완료를 확정하지 않는다.
- 확인: 첫 실패 집합에서의 복구 성공·비용, 검증기의 잘못된 통과, 전체 완료 비용을 측정한다. [E02](EVALUATION.md#e02), [E03](EVALUATION.md#e03).

## I04

**완료 비용을 기준으로 정책 선택.**

- 제안: 작업 난이도 외에 검증·탐색·복구 비용을 포함해 정책을 비교한다. 비싼 초기 실행이 재작업을 줄여 더 경제적일 가능성도 기록한다.
- 경계: Decisions의 점수를 성공 확률로 대입하지 않는다. 아직 데이터가 없으면 명시적 규칙과 보수적인 기본값을 사용한다.
- 확인: 후보의 성공·실패 패턴이 달라지는 합성 표와 실제 결과 표에서 선택이 어떻게 달라져야 하는지 검토한다. [E01](EVALUATION.md#e01), [E02](EVALUATION.md#e02).

## I05

**요청·런타임·서비스 설정의 증거 구분.**

- 제안: 정책이 요청한 설정, 런타임의 시작·변경 보고, 서비스가 보고한 모델 정보를 각각 기록한다. 모델과 effort의 관측 수준도 따로 표시한다.
- 경계: hook 성공이나 설정 파일 읽기만으로 실제 추론 전체를 증명하지 않는다. native 모드가 필수 제약을 충족하지 못하면 시작 전에 외부 worker 모드를 고른다.
- 확인: 프로필 덮어쓰기, hook 누락, effort 미보고, 모델 변경 사례가 서로 다른 상태로 남아야 한다. [E05](EVALUATION.md#e05).

## I06

**시도 ID와 취소·중복 실행 방지.**

- 제안: 시작 의도, process group·session ID, 산출물·검증·부모 수락을 attempt ID로 연결한다. 취소 요청과 종료 확인을 구분한다.
- 경계: 실행됐지만 응답만 잃었을 수 있으므로 확인 전 대체 작업을 시작하지 않는다. 자체 ID만으로 외부 부수효과의 exactly-once를 보장하지 않는다.
- 확인: 시작 직후·산출물 생성 후·수락 직전 오류를 주입해 중복 실행·중복 정산·오래된 결과 수락을 막는지 검사한다. [E05](EVALUATION.md#e05).

## I07

**부모 통합·최종 검증 예산 확보.**

- 제안: worker를 배정하기 전에 부모의 결과 통합·검증 자원을 확보하고, 나머지 예산 안에서 하위 작업을 시작한다.
- 경계: 토큰뿐 아니라 맥락 전달, 준비 시간, 대기와 공유 자원 충돌을 본다. 미확인 사용량을 무조건 0으로 처리하지 않는다.
- 확인: 동시 worker가 완료용 예약 자원을 소진하지 못하고, 같은 분해에서 전체 완료 효율이 유지되는지 검증한다. [E06](EVALUATION.md#e06).

## I08

**단계별 맥락 수집.**

- 제안: 기존 작업 정보와 저렴한 로컬 사실부터 사용하고 필요한 경우에만 관련 발췌·모델 기반 탐색을 추가한다.
- 경계: 분류를 위해 사실상 전체 작업을 먼저 수행하는 구조를 피한다. 같은 질문에 더 높은 확신이 나온 것만으로 유용성을 판단하지 않는다.
- 확인: metadata-only, 단계별 수집, 넓은 선행 수집의 총비용·완료 품질을 비교한다. [E04](EVALUATION.md#e04).

## I09

**작업별 모델·effort 결과 표.**

- 제안: 같은 개발 과제를 후보 프로필에서 각각 실행해 성공·비용·시간·실패 이유를 쌓는다. 어느 모델이 다른 모델의 실패를 보완하는지도 본다.
- 경계: 더 높은 프로필이 항상 잘한다는 순서를 강제하지 않는다. 사후 최선 선택은 관측한 범위의 참고값이고 미실행 조합은 unknown이다.
- 확인: 사후 최선 선택에도 개선 여지가 작으면 라우터 고도화를 보류하거나 과제 범위를 바꾼다. [E01](EVALUATION.md#e01).

## I10

**관찰 모드와 정책 재생.**

- 제안: 처음에는 고정 프로필로 실제 작업을 실행하면서 Decisions의 선택만 기록한다. 저장한 신호에 여러 버전의 정책을 적용해 선택 변화를 살핀다.
- 경계: 미실행 추천 경로가 성공했을 것이라고 보고하지 않는다. 다른 질문·입력·분류 모델이 필요한 정책은 기존 신호만으로 완전히 재생할 수 없다.
- 확인: 정책 불일치와 비용 추정의 출처를 표시하고, 성능 주장에는 실제 비교 실행을 사용한다. [E07](EVALUATION.md#e07).

## I11

**작업군별 정책 보정.**

- 제안: 문서·디버깅·설계, 한국어·영어, 저장소 범위별로 과소 배정과 검증 실패를 확인한다. 데이터가 부족한 군은 공통 기본 정책으로 돌아간다.
- 경계: 작은 집합에 임계값을 과도하게 맞추지 않는다. 동일 버그의 변형이 튜닝과 평가 양쪽에 들어가지 않게 한다.
- 확인: 새 저장소·새 작업군의 잠금 평가에서 보정의 이득과 회귀를 함께 보고한다. [E07](EVALUATION.md#e07).

## I12

**증거가 변한 경계에서만 재선택.**

- 제안: 하나의 실행 시도에서는 경로를 고정하고, 범위 확대·새 제약·검증 실패 같은 사건이 생겼을 때 남은 비용을 기준으로 전환을 검토한다.
- 경계: 작은 점수 변화로 모델을 반복 교체하지 않는다. 전환 시 맥락·산출물 전달 비용을 포함하고, 복구 과정의 자동 하향 변경은 초기 범위에서 제외한다.
- 확인: 작은 점수 흔들림은 전환을 만들지 않고, 중요한 새 증거에는 제한된 재선택이 일어나야 한다. [E05](EVALUATION.md#e05).

## I13

**계획·구현·검토 역할별 자원 배정.**

- 제안: 작업 유형과 함께 역할을 사용해 부모 계획·결과 통합·구현 worker·검토자에 서로 다른 설정을 시험한다.
- 경계: 비싼 부모와 검토자가 전체 비용을 지배할 수 있다. 에이전트 수를 늘리는 것만으로 품질이 좋아진다고 가정하지 않는다.
- 확인: 동일 분해·worker 수·검증 기준에서 역할별 배정만 바꾸고 오류 누락과 전체 비용을 비교한다. [E06](EVALUATION.md#e06).

## I14

**버전과 내용이 일치하는 분류 캐시.**

- 제안: 작업·관련 파일 내용·질문·정책·모델·프로필·제약 버전이 일치하는 분류 결과를 짧은 유효기간 안에서 재사용한다.
- 경계: 캐시된 분류와 예전 실행 산출물 재사용은 다른 기능이다. 예산·접근 권한·환경 상태는 매번 확인한다. 문장이 비슷하다는 이유만의 의미 기반 캐시는 나중에 검토한다.
- 확인: 파일·미커밋 diff·정책·모델 변경 시 cache miss가 되고 동일 조건에서는 호출이 줄어드는지 측정한다. [E04](EVALUATION.md#e04), [E07](EVALUATION.md#e07).

## I15

**모델·환경 변경 감지와 정책 복귀.**

- 제안: Codex·SDK·프로필·hook 변경으로 검증이 오래됐는지 표시한다. 새 정책은 일부 허용된 평가 작업에서 시험하고 이전 버전으로 돌아갈 수 있게 한다.
- 경계: 기존 실행의 정책을 중간에 몰래 바꾸지 않는다. 반복되는 인프라 오류의 임시 배정 중단과 접근 거부·refusal 우회를 구분한다.
- 확인: 버전 변경 후 예전 검증을 현재 증거로 표시하지 않고, 복귀가 이후 실행부터 적용돼야 한다. [E05](EVALUATION.md#e05), [E07](EVALUATION.md#e07).

## I16

**선택 이유·예산을 보는 CLI 화면.**

- 제안: `explain --run-id`에서 후보 제외 이유, route source, 선택 규칙, 요청·관측 설정, 검증·추정 비용을 한 번에 보여준다. 나중에 비용·시간·품질 우선 모드를 추가할 수 있다.
- 경계: 우선 모드는 품질·권한·명시 설정을 자동 완화하지 않는다. 실행하지 않은 대안의 비용·성공은 추정 또는 미측정으로 표시한다.
- 확인: 사용자가 왜 그 모델이 선택됐고 무엇이 미확인인지 구분할 수 있는 예시 출력을 검토한다. [E05](EVALUATION.md#e05), [E07](EVALUATION.md#e07).

## I17

**후속 시각화와 실행기 어댑터.**

- 제안: CLI 기록을 기반으로 작업 흐름, 선택 모델, 재시도, 누적 비용을 보여준다. 필요하면 픽셀 에이전트 표현을 관찰 화면으로 연결한다.
- 경계: 실행 핵심은 화면과 독립적으로 동작한다. 처음부터 새 GUI·범용 플러그인 시스템·여러 실행기를 동시에 만들지 않는다.
- 확인: 기존 기록만으로 한 작업을 정확하게 재구성할 수 있어야 한다. 시각화는 실제 이벤트를 나타내며 없는 agent 활동을 만들지 않는다. [E05](EVALUATION.md#e05).

## I18

**로컬·클라우드 처리와 적재 비용.**

- 제안: 원격 전송 조건을 먼저 확인한 뒤 실행기별 지원 능력과 현재 모델 적재 상태를 사용한다. 로컬 모델의 준비·교체 시간과 장치 자원 경쟁을 측정한다.
- 경계: 원격 Decisions 분류를 거쳤으면 로컬 전용 흐름이 아니다. 실행기마다 다른 thinking·effort·출력 제어를 같은 문자열 하나로 보장하지 않는다.
- 확인: local-only의 원격 요청 0회, 지원하지 않는 옵션 탐지, 실제 완료 시간·품질·장치 자원 사용을 검증한다. [E08](EVALUATION.md#e08).

## I19

**비교 데이터로 학습하는 정책.**

- 제안: 충분한 후보별 결과가 쌓이면 단순한 보정·예측 모델이 수동 규칙보다 유리한지 오프라인으로 시험한다.
- 경계: 현재 정책이 선택한 실행만 모은 로그는 선택 편향이 있다. 고가 모델이 어려운 과제만 받았다는 사실을 무시해 성능이 낮다고 결론내리지 않는다. MVP에 온라인 bandit을 넣지 않는다.
- 확인: 독립된 과제군에서 규칙·무작위 비율·cascade보다 나은지 확인하고, 지원하지 않는 반사실 비교는 unknown으로 둔다. [E07](EVALUATION.md#e07).

## I20

**재현 가능한 평가 자료와 연구.**

- 제안: 공유 가능한 과제·프로필 계약·원시 사용량·검증 결과를 묶어 모델 선택과 effort 선택, 부모·worker 자원 배정의 효과를 재현할 수 있게 한다.
- 경계: 기존 모델 라우팅 연구가 있으므로 범용 라우팅 자체의 신규성을 주장하지 않는다. 비공개 저장소·개인 데이터·실험 로그는 별도 공유 권한 없이 공개하지 않는다.
- 확인: 다른 환경에서 고정된 과제 버전·평가 기준으로 결론의 범위를 검토할 수 있어야 한다. 연구 기여와 성능 우위는 검증할 가설로 유지한다. [관련 연구](EVALUATION.md#관련-연구와-설계에-반영한-점).

## 다음 선택 기준

첫 구현은 PLAN의 M0–M2에 집중한다. 결과 표와 필수 비교에서 이득이 확인되면 P1을 선택한다. GUI, 로컬 자원 스케줄링, 학습 정책, 공개 벤치마크는 각각의 선행 조건이 충족될 때 진행한다. 각 아이디어의 상태를 바꿀 때는 관련 실행 기록·정책 버전·검토 결과를 함께 연결한다.
